# テキストのみデータの混合学習計画

## 背景

- v1.2 の Text loss (0.971) は v1.1c (0.798) より高く、tempformer の日本語テキスト生成能力に改善余地がある
- 元の Moshi は英語ベースのため、日本語テキストの語彙・文法学習が不十分
- テキストのみデータを混ぜることで、音声データを増やさずにテキスト能力を強化できる可能性がある

## データ形式

既存の学習データは `(9, T)` の shape:
- Row 0: テキストトークン（text_padding_token_id = 3 が無音区間）
- Row 1-8: オーディオ codebook トークン（Mimi の 8 codebooks）

テキストのみデータの場合:
- Row 0: 日本語テキストトークン（実際のテキスト）
- Row 1-8: 無音/サイレンストークンで埋める

## 実装方針

### テキストのみデータの作成

1. 対話形式の日本語テキストを収集
2. SentencePiece (tokenizer_spm_32k_3.model) でトークナイズ
3. テキストトークンを Moshi のフレームレート (12.5Hz) に合わせて配置
   - 通常のテキストは音声と同期して間隔を空けて配置される（大部分が padding=3）
   - テキストのみの場合は、密に配置するか、適度に padding を挟むか検討が必要
4. オーディオ codebook は無音トークンで埋める

### 学習設定

- ベースモデル: v1.2 の J-CHAT 完了チェックポイント (step_8880_fp32) または v1.2 最終 (step_9282_fp32)
- テキストデータ割合: Zoom1 データの 10-20% 程度（少量から開始）
- `audio_loss_weight_when_text_pad`: 0.0 or 0.1（テキストのみフレームで audio loss を抑制）
- その他の設定は既存の Zoom1 学習と同一

### テキストデータ候補

- **対話形式テキスト**（最有力）
  - 小説・脚本の会話部分
  - 対話コーパス（テキストのみ）
  - LLM で生成した対話テキスト
- Wikipedia 日本語
- llm-jp コーパス
- CC-100 日本語

対話モデルなので、**対話形式のテキスト**が最も効果的と考えられる。

## 検証ポイント

- [ ] テキストのみデータ混合で Text loss が下がるか
- [ ] Audio loss / 音声品質に悪影響がないか（catastrophic forgetting）
- [ ] 実際の対話品質（発話の自然さ、応答の適切さ）に改善が見られるか

## 注意点

- テキストデータが多すぎると音声能力の catastrophic forgetting リスクがある
- 音声とテキストの同期（フレームレート合わせ）の実装が必要
- zero_token_id = -1 は ignore_index として使われるため、無音トークンは別途決定する必要がある
